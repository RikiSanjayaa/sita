# E2E coverage map

Maps user flows to Playwright specs in `tests/e2e/specs/`. E2E covers cross-role flows a user can see; business rules (validation, calculations, detailed permissions) stay in Pest.

**Rule for feature issues:** a pull request that adds or changes a user-visible flow MUST update this file (row, status, spec) in the same change, and add or update the Playwright scenario. Menus come from `resources/js/config/role-navigation.ts`; keep the rows below in sync with it.

Status: **tercakup** = main flow has a spec, **sebagian** = some steps or roles covered, **belum** = no spec. Priority: **P1** core thesis workflow or demo path, **P2** supporting, **P3** admin/support.

Status tersebut berlaku untuk alur yang disebut pada barisnya, bukan seluruh cabang pemulihan. Bedakan transisi UI, transisi campuran service/Tinker, fixture status dan Pest saja; audit recovery di bagian akhir melacak batasnya di #140.

## Fixtures

- `thesisScenarios` in `support/thesis-fixtures.ts` lists the shared seeded students (`akbar`, `nadia`, `putra`, `mahasiswa`, ...). Earlier specs change their state (reschedule, finalize, close), so do not depend on their initial state.
- Dedicated scenario students come from `database/seeders/PlaywrightScenarioSeeder.php` (run by the setup project, not by `DatabaseSeeder`). Specs call `seedPlaywrightScenarios()` in `beforeAll` to rebuild them: `twoSupervisors` (dosen1 + dosen2), `semproTwoExaminers` (dosen3 + dosen4), `semproUnscheduled`, `passedWithoutSupervisors`, `sidangWithPanel` (dosen1, dosen2, dosen3). Add new scenario students there plus an entry in `thesisScenarios`. Scenarios for OBE, expired ticket and archived students are added by the feature issues themselves (`completedInGrace`, `completedPastGrace`: issue #27).
- The `kaprodi` account (`kaprodi@sita.test`) has a stored auth state like the other accounts.
- `golden-path` owns a fresh student (`GoldenPathScenarioSeeder`, `support/golden-path.ts`) and removes its academic records and uploaded files after the run, including failures. Staff use separate contexts with the setup project's auth states; every academic transition is performed through the UI, with a screenshot attached per stage.
- `thesis-recovery` uses `RecoveryScenarioSeeder` for fresh, research, scheduled Sempro and scheduled Sidang starting states. Each test recreates the rehearsal student and owns its cleanup; it does not reset shared scenario students. Admin, student and lecturers have separate browser contexts. All recovery transitions use UI controls; seed/service calls only establish starting conditions and remove owned data.
- Retry scheduling waits for the time picker to display the entered value before submitting the admin form; no fixed sleep or additional retry masks delayed widget updates.
- Katalog validasi review dokumen mengirim token CSRF sesi dari meta halaman lewat header pada request review saja. Clock server katalog membuat cookie `XSRF-TOKEN` kedaluwarsa terhadap clock browser sebenarnya; tanpa header, redirect sesi dapat disangka respons validasi. Capture tetap menekan tombol UI dan memeriksa pesan validasi server.
- Pemeriksaan batas drawer berkas ujian menunggu posisi akhir animasi sebelum mengukur viewport; ukuran drawer yang benar-benar melampaui layar tetap menggagalkan pemeriksaan.
- Pengelolaan jadwal dosen berada pada drawer detail sesi yang sama dengan catatan hasil bimbingan. Ikon mata, klik baris dan Enter/Space membuka drawer; kontrol selesai/batal hanya muncul pada sesi mendatang yang dapat dikelola. `student-activity`, `jadwal-bimbingan`, dan `golden-path` memakai drawer ini (#157). Reproduksi macet Firefox fisik masih membutuhkan rekaman; loop natural-motion lokal bukan bukti GPU perangkat pengguna.
- Bukti screenshot drawer menunggu seluruh animasi finite dan memeriksa tepi panel pada viewport, lalu menangkap viewport saja saat dialog terbuka. Capture di tengah slide dan full-page yang memperpanjang latar di bawah overlay bukan bukti drawer macet.
